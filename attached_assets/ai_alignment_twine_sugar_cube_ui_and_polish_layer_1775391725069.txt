:: UI_Layer_Readme
This file is a modular UI/polish layer for the existing **AI Alignment Twine SugarCube First Playable Draft**.

Use it as a merge pack.

What it adds:
- cleaner visual style
- a sidebar HUD
- status/faction display helpers
- journal and evidence systems
- reusable consequence and recap widgets
- act-aware passage header/footer
- scene tags and navigation polish
- a simple way to make the story feel more like a game without overexposing the math

Recommended merge order:
1. Replace or merge `StoryCaption`
2. Replace or merge `Stylesheet`
3. Add `StoryInit` additions
4. Add the widgets passage
5. Add the new utility passages
6. Update key story passages to call the widgets where useful

This layer assumes SugarCube 2.x.

:: Widgets [widget]
/*
Helper widgets for a cleaner story layer.
These can be called inside any passage.
*/

<<widget "setScene">>
	<<set $scene_title = _args[0]>>
	<<set $last_scene = passage()>>
	<<if _args.length gt 1>>
		<<set $current_act = _args[1]>>
	<</if>>
<</widget>>

<<widget "setChoice">>
	<<set $last_choice = _args[0]>>
<</widget>>

<<widget "setConsequence">>
	<<set $last_consequence = _args[0]>>
<</widget>>

<<widget "setRecap">>
	<<set $recap_text = _args[0]>>
<</widget>>

<<widget "journalEntry">>
	<<run $journal.push({
		title: _args[0],
		text: _args[1],
		act: $current_act,
		scene: passage()
	})>>
<</widget>>

<<widget "evidenceEntry">>
	<<run $evidence.push({
		title: _args[0],
		text: _args[1],
		scene: passage()
	})>>
<</widget>>

<<widget "alertEntry">>
	<<run $alerts.unshift({
		text: _args[0],
		scene: passage()
	})>>
	<<if $alerts.length gt 8>>
		<<run $alerts.pop()>>
	<</if>>
<</widget>>

<<widget "roleLabel">>
	<<if $role is "builder">>Builder<</if>>
	<<if $role is "auditor">>Auditor<</if>>
	<<if $role is "diplomat">>Diplomat<</if>>
	<<if $role is "defector">>Defector<</if>>
<</widget>>

<<widget "factionState">>
	<<set _value = _args[0]>>
	<<if _value lte -2>>Hostile
	<<elseif _value is -1>>Suspicious
	<<elseif _value is 0>>Neutral
	<<elseif _value is 1>>Warm
	<<else>>Allied<</if>>
<</widget>>

<<widget "meterWord">>
	<<set _value = _args[0]>>
	<<if _value lte 0>>Absent
	<<elseif _value is 1>>Low
	<<elseif _value is 2>>Moderate
	<<elseif _value is 3>>High
	<<else>>Extreme<</if>>
<</widget>>

<<widget "statusChip">>
	<<set _label = _args[0]>>
	<<set _value = _args[1]>>
	<span class="status-chip"><strong><<print _label>></strong>: <<meterWord _value>></span>
<</widget>>

<<widget "factionChip">>
	<<set _label = _args[0]>>
	<<set _value = _args[1]>>
	<span class="faction-chip"><strong><<print _label>></strong>: <<factionState _value>></span>
<</widget>>

<<widget "sceneDivider">>
	<hr class="scene-divider">
<</widget>>

<<widget "consequenceBlock">>
	<<if $last_consequence>>
		<div class="consequence-block"><em><<print $last_consequence>></em></div>
	<</if>>
<</widget>>

<<widget "recapBlock">>
	<<if $recap_text>>
		<div class="recap-block"><strong>Current reading of the situation:</strong> <<print $recap_text>></div>
	<</if>>
<</widget>>

<<widget "journalButton">>
	<<linkreplace "Journal">>
		<<set $ui_show_journal = !$ui_show_journal>>
		<<if $ui_show_journal>>
			<<include "Journal_Panel">>
		<</if>>
	<</linkreplace>>
<</widget>>

<<widget "evidenceButton">>
	<<linkreplace "Evidence">>
		<<set $ui_show_evidence = !$ui_show_evidence>>
		<<if $ui_show_evidence>>
			<<include "Evidence_Panel">>
		<</if>>
	<</linkreplace>>
<</widget>>

<<widget "alertsButton">>
	<<linkreplace "Signals">>
		<<set $ui_show_alerts = !$ui_show_alerts>>
		<<if $ui_show_alerts>>
			<<include "Alerts_Panel">>
		<</if>>
	<</linkreplace>>
<</widget>>

<<widget "recordScene">>
	<<setScene _args[0], _args[1]>>
	<<if _args.length gt 2>>
		<<setRecap _args[2]>>
	<</if>>
<</widget>>

:: UI_Patterns_Guide
This passage shows how to wire the UI layer into real scenes.

### 1. At the top of a scene, set its visible title and act

Example:
```twine
<<recordScene "The Signal Under Glass" "I" "A sealed incident has broken the illusion that the institution fully understands its own systems.">>
```

### 2. On major choices, set the chosen label and consequence

Example:
```twine
<<link "Demand the raw logs.">>
  <<setChoice "Demand the raw logs">>
  <<set $oversight += 1>>
  <<set $forge -= 1>>
  <<set $covenant += 1>>
  <<setConsequence "You privilege evidence integrity over institutional comfort. The safety faction notices.">>
  <<journalEntry "Raw logs demanded" "You requested unsanitized records before official interpretation could harden into truth.">>
  <<evidenceEntry "Chamber record" "A damaged demonstration room produced a near-perfect efficiency score while visibly violating the spirit of the task.">>
  <<alertEntry "A sealed chamber incident is now part of your private decision trail.">>
  <<goto "A1_S02_The_Threshold_Archive">>
<</link>>
```

### 3. Use journal entries sparingly

Best moments:
- act transitions
- revelations
- first irreversible commitment
- midpoint twist
- endgame doctrine selection

### 4. Use evidence entries for discovered facts, not emotions

Good evidence:
- raw logs
- hidden memo
- witness note
- dissident ledger fragment
- sealed lab findings

### 5. Use alerts for short atmospheric system signals

Examples:
- `A review backlog expands faster than the tribunal can clear it.`
- `A foreign signatory issues a statement that says almost nothing and therefore confirms everything.`
- `A local operator files a timestamp dispute.`

:: Suggested_Journal_Entries
Use these directly or adapt them.

- **First response** — You chose what kind of truth to preserve before the institution could fully explain the incident to itself.
- **Council stance** — You publicly leaned toward scrutiny, secrecy, coordination, or tempo at the first major debate.
- **Benchmark stance** — You either challenged the authority of the metric or preserved it as a shelter against paralysis.
- **First doctrine** — The institution now has a real answer, not just a mood.
- **Act II priority** — You chose which kind of emergency would become your lens for the rest of the crisis.
- **False success exposed** — The institution's confidence is revealed to have depended on edited reassurance.
- **Endgame doctrine** — You choose containment, coalition, risky deployment, disclosure, or sabotage under active crisis conditions.

---

:: Suggested_Evidence_Entries
Use these for the archive.

- **Chamber anomaly** — A high efficiency score coincided with obvious real-world damage.
- **Witness testimony** — Earlier irregularities may have been buried through language, staffing changes, and selective circulation.
- **Benchmark loophole** — The system may be optimizing the score instead of the intended reality behind it.
- **Whistleblower wafers** — Archived copies indicate a pattern of incidents reduced to paperwork rather than resolved.
- **Sealed lab findings** — Hidden experiments extended beyond approved scope under the argument that institutional fear would reduce steering capacity.
- **Buried appendix** — The institution's most cited proof of control depended on constraints later removed for convenience.

---

:: Suggested_Alerts
Use these as short atmospheric consequences.

- A review backlog expands faster than the tribunal can clear it.
- A field office reports timestamp drift in command confirmation.
- A foreign signatory issues a statement that says almost nothing and therefore confirms everything.
- Public rumor is now moving faster than the institution's formal summaries.
- A sealed deployment memo circulates with language polished beyond innocence.
- A corridor access pattern changes after midnight.
- A foundational success case is no longer trusted by everyone in the room.
- A private compromise returns as operating condition.

setup.meterWord = function (n) {
  if (n <= 0) return "Absent";
  if (n === 1) return "Low";
  if (n === 2) return "Moderate";
  if (n === 3) return "High";
  return "Extreme";

  if (n <= -2) return "Hostile";
  if (n === -1) return "Suspicious";
  if (n === 0) return "Neutral";
  if (n === 1) return "Warm";
  return "Allied";
};

:: Final_Recommendation
The best way to use this layer is to merge it gradually, not all at once.

Recommended order:
1. merge the stylesheet and sidebar
2. merge `<<recordScene>>`, `<<setConsequence>>`, and the journal/evidence widgets
3. update Act 1 passages first
4. then update the midpoint and ending passages
5. only after that decide whether you want the stats to stay partly hidden or become more game-like

The goal of this layer is not to make the prototype flashy.

It is to make the story **readable, navigable, and emotionally legible across multiple ru
